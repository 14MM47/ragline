# The test corpus

ragline is evaluated on 803 datasheets, manuals and catalogues for industrial
automation equipment — HMIs, PLCs, drives, distributed control systems, I/O,
networking, safety, sensors and instrumentation — from 46 vendors.

**The PDFs are not in this repository.** They are published by their vendors
for anyone to download, but they remain the vendors' copyright and are not
ours to redistribute. What is here instead is an index: enough to know exactly
which documents the evaluation used, to fetch them yourself, and to check that
what you fetched is what was evaluated.

| File | What it is |
|---|---|
| [manifest.csv](manifest.csv) | One row per document — the machine-readable index |
| [INDEX.md](INDEX.md) | A summary by category, and the `hmi/` documents in full with the golden questions that cite each one |

Both are generated by `scripts/build_corpus_index.py`.

## Why it matters for the golden set

The golden questions name their sources by corpus path:

```json
"expected_sources": ["hmi/allen-bradley/panelview-800/panelview_800_technical_data.pdf"]
```

Without the corpus that is just a string. The index ties it to a specific
document — its title, its page count, the digest of the exact revision, and
where it was downloaded from — so a question, its expected answer and its
quoted evidence can be checked against the source.

The recorded runs ingest the whole `hmi/` category (119 documents). 68 of them
are cited by at least one question; the other 51 are there because a retriever
that only ever sees the right documents is not being tested.

## Layout

```
<category>/<vendor>/<product-family>/<descriptive_name>.pdf
hmi/weintek/cmt-x-series/cmt3072xh_datasheet.pdf
```

File names were normalised when the corpus was collected; they are not the
vendors' original file names. The original name is usually visible at the end
of the source URL.

## manifest.csv columns

| Column | Meaning |
|---|---|
| `path` | Location in the corpus tree; the string golden sets use |
| `category`, `vendor`, `product_family` | The three directory levels of `path` |
| `title` | The title in the PDF's own metadata — often the publication title, sometimes empty or an authoring-tool file name |
| `pages` | Page count |
| `size_bytes` | Exact file size |
| `sha256` | Digest of the file as evaluated |
| `source_url` | The public URL it was downloaded from; empty when not recorded |
| `golden_questions` | Ids from `eval/golden_set_hmi.json` whose `expected_sources` include this file |

## Fetching it

```bash
python scripts/fetch_corpus.py --golden-only     # the 68 cited documents
python scripts/fetch_corpus.py --category hmi    # the evaluated subset, ~0.7 GB
python scripts/fetch_corpus.py                   # everything with a URL, ~5 GB
```

Files land under `./testdata/` (or `--dest`, or `$RAGLINE_CORPUS_DIR`) in the
layout above. The script downloads one file at a time with a pause between
requests, skips files already present with the right digest, and never
overwrites a file that differs unless told to with `--force`.

Three outcomes need a person:

- **No URL recorded.** 153 documents (41 of them in `hmi/`, 22 of those cited
  by the golden set) were collected by hand before downloads were logged. The
  script lists them with title and digest. Most can be found by searching the
  vendor's site for the title or the product name; put the file at its `path`
  and re-run to check the digest.
- **Changed.** The file downloaded but its digest differs: the vendor has
  probably published a new revision at the same address. It is kept. Answers
  may still be right, but page numbers in the golden set can shift.
- **Failed.** The address no longer serves a PDF. Vendors reorganise their
  download sites; the title and digest are what is left to search with.

URLs were live when the corpus was collected (mid-2026) and are not monitored.

## Regenerating the index

With the PDFs on disk:

```bash
python scripts/build_corpus_index.py --corpus-dir testdata
```

Source URLs are taken from a fetch log beside the PDFs when there is one, and
otherwise carried over from the existing `manifest.csv`, so re-running never
loses a URL. SHA-256 is recomputed from every PDF on disk, even when its size
matches the fetch log. The script exits non-zero if a golden set cites a
document the corpus does not contain.

## Using your own documents

Nothing in ragline is specific to this corpus. Ingest any directory of PDF,
DOCX or XLSX files, write a golden set against it in the format described in
[docs/evaluation.md](../../docs/evaluation.md), and the same harness applies.
