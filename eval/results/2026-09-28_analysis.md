## What the three confident errors have in common

All three (A11, D02, D05) are **table-reading errors inside the right document**: a wrong row or
column picked from a flattened specification table. None is a retrieval failure and none is a
hallucination from outside the sources. That is the behaviour to A/B against the larger 30B-A3B
"balanced" stack: if it reads the same tables correctly, the 27B INT4 is paying for its size here; if
it makes the same mistakes, the fix is chunking/table rendering, not the model.

## Abstentions are retrieval and chunk-content problems, not model ones

A01 (flattened table), A09 (blank row in chunk), B04 (section 7.8 never retrieved), B11 (second
product's manual never retrieved), D10 (datasheet chunk has no body text). The model's refusal wording
is consistent and it never substituted a neighbouring model's value — the same discipline it showed on
all six unanswerables.

## Comparison questions: one side retrieved

Two of the ten comparisons (B11, D10) got only one product's document into the top-8 after reranking,
and four more (A10, A12, C10, C11) answered correctly but cited only one of the listed documents. For a
two-product question a single query embedding lands on whichever product dominates the phrasing.
Worth a per-entity retrieval split in ragline before the next pass.

## Answer style

Well-cited (100% carry citations, pages sane), quotes the exact table line when confident, one-line
answers when the fact is simple, verbose only when uncertain. Thinking-off template works. The
follow-ups without context produce long generic spec dumps (500–860 completion tokens, 10–13 s).

   to `evaluate.py`; six of 45 source hits were not correct answers.
2. **Follow-ups need their previous turn.** Add a `previous_turn` field to the golden set and let the

3. **Library questions (E07–E09) need a document-listing tool**, not retrieval. Keep them, score
   them separately, expect 0/3 on every stack until that exists.
4. **Verify three expected answers against the PDFs:** A01 (11 W), D02 (2.74 kg vs 1.6 kg), C11

# Addendum 2026-09-29: the same stack on a real Ampere card (1x RTX A6000)

Run: `2026-09-29_ragline-3090-on-a6000.json` (profile `ragline-3090-on-a6000`, $0.53/hr at the time).
Same weights, budgets, ragline revision and golden-set digest as the PRO 6000 run.

| | PRO 6000 (2026-09-28) | A6000 (2026-09-29) |
|---|---|---|
| Source hit-rate (set's rule) | 45/51 = 0.88 | 44/51 = 0.86 |
| Answer correctness, 46 answerable | 37 C / 5 A / 3 W / 1 N | 37 C / 6 A / 2 W / 1 N |
| Unanswerable | 6/6 declined | 6/6 declined |
| Latency median / p90 / max | 6.5 / 12.1 / 36.1 s | 11.6 / 25.9 / 44.2 s |
| Whole set | 7.6 min | 14.0 min |
| Completion tokens ÷ latency, long answers (lower-bound decode proxy) | 42.5 tok/s | 23.8 tok/s |
| Tokens | 292k | 293k |

**Boot on Ampere (the point of this run):** all three services healthy from a fresh create — sm_86
TEI router, INT4 27B with fp8 KV on FlashInfer, vLLM reranker. No fallback rung needed.

**Answers are the same stack's answers.** 59 of 60 land on the same conclusion; the wording differs
slightly because the Ampere kernels produce slightly different logits. Changes:
- D05 (G315C weight): the PRO 6000 run confidently mapped G315C to the G15 row (wrong); the A6000 run
  abstains ("weight not listed for the G315C"). Better behaviour, same underlying table problem.
- A01: now states 34 BTU/hr as the power figure "listed as heat dissipation" instead of abstaining —
  slightly worse framing, same missing-11 W chunk.
- D07: still the right 22.5 mm cutout, but cited the STW/SP manuals instead of the STM one, so the
  automatic source rule counts it as a miss. Answer correct.
- A11 and D02: the same two confident table misreads on both cards.

**Speed, scaled to a 3090.** The A6000 has 82% of a 3090's bandwidth; multiply by ~1.22: expect a
median of ~9.5 s per question and ~29 tok/s on the decode proxy on the pair, ~11.5 min for the set.
The PRO 6000 numbers were the upper bound (1.9x bandwidth); the pair sits between the two runs, nearer
the A6000.
